- **Payments:** RevenueCat (entitlements) + Stripe (web checkout). (OBSERVED.)
- **iOS shell:** native wrapper around the web app + a **keyboard extension** target.

## Core data flow — screenshot coaching (OBSERVED shape)
1. User screenshots a chat; in the app or keyboard, taps **Coaching**.
2. Client calls `coaching-ai` with `{ body, headers: <auth> }`. Observed body keys across
   AI calls include `message`, `tone`, `context`, `platform`, `userId`, `token`.
   (INFERRED: the screenshot image is uploaded/OCR'd or vision-analyzed server-side; the
   client-side provider is hidden, so vision+LLM happens in the edge function.)
3. `coaching-ai` returns `{ allowed, consentRequired, error, ... }` — i.e. the server enforces
   **consent gating** and **quota/entitlement gating** before returning suggestions. (OBSERVED:
   `H.consentRequired`, `H.allowed===false`, `H.error` branches around the invoke.)

## Keyboard-extension auth — the interesting bit (OBSERVED)
The keyboard extension can't carry the full app session, so REF issues it a scoped token:
```js
// issue
functions.invoke("keyboard-token", { body: { action:"issue",
    ...(deviceId && {device_id}), ...(deviceId && replacesHash && {replaces_hash}) },
    headers: <session auth> })
// revoke
functions.invoke("keyboard-token", { body: { action:"revoke", ...(deviceId && {device_id}) }, headers })
```
INFERRED: the main app (which holds the Lovable Cloud session) mints a **device-scoped,
revocable token** that the keyboard extension stores in a shared App Group and sends on
its own `coaching-ai`/icebreaker calls. `replaces_hash` implies token rotation. This is a
clean pattern for giving a sandboxed app extension least-privilege API access — directly
relevant to FlirtPilot's IME→backend trust boundary.

# 04 — iOS Binary RE Methodology (runnable; pending IPA)

The IPA is **not available in this environment** (no Apple device/account), so this is a
**runnable procedure**, not results. Installed tools live under `E:\reverse-engineering\`:
`ghidra`, `cutter`, `retdec`, `frida` (`jadx` = Android, N/A here).

Because REF is a Lovable **web app in a native shell**, expect the Mach-O to be thin: a
WKWebView/Capacitor host + RevenueCat + the keyboard extension. The high-value targets are

## Step 0 — Obtain and decrypt the IPA (needs a real device)
App Store binaries are FairPlay-encrypted; you must decrypt on-device.
```bash
# On a jailbroken iPhone (frida-ios-dump is the common path):
pip install frida-tools
git clone https://github.com/AloneMonkey/frida-ios-dump
# install REF from the App Store first, then:
python3 dump.py -o REF.ipa "REF: Dating Coach"     # pulls a decrypted IPA
# Non-jailbroken alt: a dev-signed sideload + a decrypt tweak, or a MobileSubstrate-free
# userland decryptor. Document whichever you use.
unzip -o REF.ipa -d REF_ipa
BIN="REF_ipa/Payload/REF.app/REF"                  # main Mach-O
```
Sanity-check it is decrypted (cryptid must be 0):
```bash
otool -l "$BIN" | grep -A4 LC_ENCRYPTION_INFO      # cryptid 0 = decrypted
file "$BIN"; lipo -info "$BIN"                      # arch(es)
```

## Step 1 — Triage strings & structure
```bash
strings -a "$BIN" | grep -Ei 'supabase|functions/v1|lovable|revenuecat|keyboard-token|coaching-ai|appgroup|group\.' | sort -u
otool -L "$BIN"            # linked frameworks (WebKit? Capacitor? RevenueCat?)
```
Confirms the shell type and whether any endpoint/App-Group id is baked natively.

# Reimplementation / Competitive Plan — REF ➜ FlirtPilot

Clean-room. We copy *ideas and architecture patterns*, never their code or assets.
Cross-reference: FlirtPilot is our Android dating-conversation keyboard + offline copilot
(Hermes profile `dating2`, repo `C:\Users\h\flirtpilot`).

## 1. Feature parity map
| REF feature (OBSERVED) | REF backend fn | FlirtPilot status | Action |
|------------------------|----------------|-------------------|--------|
| Screenshot → reply coaching | `coaching-ai` | core engine done (offline) | Add screenshot/OCR path; we can do it **on-device** (differentiator). |
| One-tap icebreakers | `line-of-the-day` | partial | Add opener generator + "line of the day" retention hook. |
| Profile review (photos/text) | `profile-review-ai` | missing | New feature; vision model. |
| Practice mode (sim partner) | `practice-ai` + `generate-practice-prompt` | missing | High-value, low-risk to build. |
| Keyboard inside any app | iOS appex + `keyboard-token` | our IME is the core | Mirror the **device-scoped revocable token** pattern for our IME→backend boundary. |
| Re-engagement nudges | `pattern-interrupt-ai` | n/a | Optional; align with our ethics line (no dark patterns). |

## 2. Architecture lessons worth copying (OBSERVED)
1. **Least-privilege extension token.** `keyboard-token` (issue/revoke, `replaces_hash`
   rotation) lets a sandboxed keyboard call the API without the full session. Adopt the same
   trust boundary: the main app mints a rotating, revocable, device-scoped token into a shared
   store; the IME uses only that. Prevents a compromised keyboard from owning the account.
2. **Server-side consent + quota gating.** `coaching-ai` returns `{consentRequired, allowed}`
   — never trust the client for entitlement or consent. Enforce in our backend too.
3. **Thin client, server-held LLM provider.** REF leaks no LLM provider client-side; all model
   calls are edge functions. Keeps keys safe and lets them swap models. (We already lean
   offline — for any cloud calls, do the same.)
4. **Retention stack as first-class backend.** `line-of-the-day`, `retention-offer`,
   `winback-checkout`, `pattern-interrupt-ai`, `email-unsubscribe`. If we monetize, these are
   the table-stakes server endpoints.

## 3. Where we can be *better*
- **Offline / on-device inference.** REF is a thin web shell; every coaching call is a network
  round-trip with consent/quota gating and a server LLM. FlirtPilot's offline copilot = privacy
  (conversation screenshots never leave the phone) + zero latency + works without Full Access /
  signal. This is our sharpest wedge — lead marketing with it.
- **Full Access honesty.** REF needs Full Access for its network features. We can keep the
  core coaching usable *without* Full Access by running on-device. Strong trust story.
- **No 17+ profanity gate / cleaner positioning** if we choose.

#!/usr/bin/env bash
# Reproducible web-recon for REF: Dating Coach (clean-room, no secrets stored).
# Usage: bash tooling/recon.sh
set -euo pipefail
ID=6803683151
OUT="$(cd "$(dirname "$0")/.." && pwd)/recon"
mkdir -p "$OUT"

# 1) App Store metadata
curl -s --max-time 25 "https://itunes.apple.com/lookup?id=${ID}" -o "$OUT/lookup.json"

# 2) Production SPA shell + main bundle
curl -s --max-time 25 -A "Mozilla/5.0" https://refdating.com -o "$OUT/site_index.html"
BUNDLE=$(grep -oE '/assets/main-[A-Za-z0-9_-]+\.js' "$OUT/site_index.html" | head -1)
curl -s --max-time 30 -A "Mozilla/5.0" "https://refdating.com${BUNDLE}" -o "$OUT/main.js"

echo "== backend domains =="
grep -oiE "https?://[a-z0-9.-]+\.(supabase\.co|lovable\.app|stripe\.com|rev\.cat|lovable\.dev)[a-z0-9/_?=.&-]*" "$OUT/main.js" | sort -u

echo "== edge functions (supabase.functions.invoke) =="
grep -oiE '\.invoke\("[a-z0-9_-]+' "$OUT/main.js" | sed 's/.*"//' | sort -u

echo "== feature keyword counts =="
for kw in coaching icebreaker profile-review screenshot subscription revenuecat stripe paywall; do
  printf "%-16s %s\n" "$kw" "$(grep -oiE "$kw" "$OUT/main.js" | wc -l)"
done
